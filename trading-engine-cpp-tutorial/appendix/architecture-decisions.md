# 架构决策记录

| 决策 | 当前约定 | 复核点 |
| --- | --- | --- |
| 01 语言与构建 | C++20、CMake 3.20 起、标准库优先。库、演示、测试各自一个目标 | Day 01、05 |
| 02 单位和金额 | 用整数 tick、lot 和币种最小单位。单价与总预算类型分开。乘加前检查可表示性 | Day 06、14、19 |
| 03 活动 ID 与排队 | `(symbol, orderId)` 在活动期间唯一，入站先查重复。FIFO 由实际入队顺序决定。减量不重排，改价重排 | Day 08、12、15 |
| 04 订单簿所有权 | 价树拥有档，档拥有订单。索引借用稳定节点。禁止整簿隐式复制或移动。重建索引后才能采用新状态 | Day 09–11、17、29 |
| 05 结果与结算 | `Result` 拥有事件和查询载荷。命令状态与执行事件分开。成交按扫描顺序，随后记录余量拒绝。结算完成再发布 | Day 07、13、19、20 |
| 06 失败边界 | 先准备并验证，再提交簿和账本。业务拒绝与内部故障有独立路径；期货 NSF 释放记录后保留 Java 的键表墓碑与零余额槽 | Day 17–19、28 |
| 07 优化顺序 | 建立参考模型和性能基线后，再试节点池和策略接口 | Day 16、21–24 |
| 08 并发 | `Engine` 单写者。异步入口用有界 mutex 队列。SPSC 是独立内存模型实验 | Day 25–27 |
| 09 恢复协议 | 按字段编码，稳定序号和版本。命令写入先于状态提交。快照索引由内容重建 | Day 28–30 |
| 10 产品范围 | 多品种现货与期货共用账本，按 Java 同结算币种规则计算余量。Java 线协议、不同币种抵扣、分片和网关作为扩展 | Day 31–32 |
| 11 期货源码行为 | 保留缺失盘口估值、最大方向保证金、开仓计费、空记录利润转账和当前 freeMargin 覆盖赋值；用实际 Java 方法核对，修正版另立语义版本 | Day 31 |
| 12 兼容次序 | 仓位 map 拥有值，独立键表复现 Eclipse 11.0.0 的顺序；键表槽位与墓碑也进入快照和指纹 | Day 31–32 |
| 13 协议演进 | v2 写入、v1/v2 读取。价格缓存与逐命令 L2 配置属于决策状态，恢复不以当前簿覆盖旧缓存 | Day 32 |

逐条行为依据见[源码报告](../00-overview/java-source-analysis.md)，接口及提交顺序见[C++ 架构](../00-overview/architecture.md)。
